# 抽象：进程

## 概念

**进程是运行中的程序**，操作系统通过**虚拟化cpu**来提供一种假象：一台计算机存在多个cpu，而每个进程都在独占一个cpu。

通过**分时共享（time sharing）**，用户可运行多个并发进程，但这会带来额外的性能损耗。

## 机器状态

进程的**机器状态（machine state）**是指进程在任意时刻的硬件上下文（hardware context）**：

- 程序计数器（PC）：下一条要执行的指令地址

- 寄存器文件：通用寄存器、栈指针（SP）、帧指针（FP）等

- 内存地址空间：代码段、数据段、堆、栈

- 打开的文件描述符、信号掩码等内核资源

## 进程创建的过程

将代码和所有静态数据从磁盘加载到内存，分配堆栈，执行IO相关的初始化任务，跳转到main()入口，程序开始启动。

## 进程API

进程api会在第五章详细讲到，这里仅提供常见api功能分类：

- 创建：创建新进程
- 销毁：强制销毁进程
- 等待：等待其他进程执行
- 控制：其他对进程控制
- 状态：获取进程状态

**由缓冲区问题引发的思考**

在OSTEP的5.3练习中，使用fork，exec，wait系统调用来让子进程运行wc，打印p3.c中的文本信息。但子进程没有正常打印信息，这是可以预见到的。

因为全缓冲机制，第一个helloworld被子进程完全复制到了缓冲区中，当然之后完成的结果也被复制到缓冲区，子进程退出时缓冲区刷新。由于某种缓冲机制和输出竞争，wc的输出结果就被覆盖了。

**我们需要在fork之前使用fflush()强制刷新缓冲区，这是一种Linux编程规范。**

  
**思考：为什么缓冲区清空数据就会被显示在终端中？**

当调用printf时的数据流向：

1. 数据先被存放在c标准库为其申请的内存中，被称为用户态缓冲区，不同进程的用户态缓冲区是独有的
2. 当缓冲区满或使用\n时，会调用write()系统调用，将用户态数据拷贝到内核态。
3. 内核找到指定的文件描述符（fd = 1），发现其是终端设备文件，于是内核调用终端处理程序
4. 驱动程序把字符发给显卡或终端模拟器，硬件显示为屏幕上的像素点。

  

## 进程调度状态

进程会处在这三种状态之一：**运行态，阻塞态，就绪态**

这些状态的转换是由操作系统进程调度所决定的。

## 进程的数据结构

操作系统通常会通过**进程列表（process list）**来跟踪当前运行的所有进程。操作系统也应该跟踪阻塞状态的进程，确保当IO操作完成时，能唤醒正确的进程。

xv6就通过proc结构体来保存进程的状态信息，linux通过进程描述符task_struct保存进程信息。教科书上会用**进程控制块Process Control Block**来描述这个结构。

在进行进程调度时，需要保存被停止的**进程上下文**（一些寄存器状态），等到处理完毕后再恢复。这项技术叫作**上下文切换**。

  

# 受限直接执行
## 受限的操作
为了限制进程权限，我们引入一种新的处理器模式，**用户模式（user mode）和内核模式（kernel mode）**。内核模式可以执行特权操作，如IO操作，访问文件系统，创建销毁进程，分配内存等。

用户模式想执行特权操作需要执行`system call` 系统调用，程序会执行`陷阱指令`，程序从用户模式提权到内核模式，执行相应操作后，返回用户态。

受限直接运行协议（LDE协议）的运行过程：
	第一阶段，系统引导阶段，内核初始化陷阱表，CPU会记住其位置方便以后调用。内核通过特权指令实现此功能。
	第二阶段，进程运行阶段，内核分配进程运行所需资源，硬件从内核栈恢复寄存器，将系统转到用户态，程序跳转到main开始执行。当调用系统调用时，会陷入操作系统，硬件保存寄存器状态，系统变更为内核模式并跳转到陷阱处理程序
