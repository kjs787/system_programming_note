## 什么是操作系统

操作系统是一种系统软件，主要功能是向下管理 CPU、内存和各种外设等硬件资源，并在此基础上形成软件执行环境，向上为应用程序提供服务。

在一般情况下，操作系统的主要组成包括：

1. 操作系统内核：操作系统的核心部分，负责控制计算机的硬件资源并为用户和应用程序提供服务。
2. 系统工具和软件库：为操作系统提供基本功能的软件，包括工具软件和系统软件库等。
3. 用户接口：是操作系统的外壳，是用户与操作系统交互的方式。用户接口包括图形用户界面（GUI）和命令行界面（CLI）等。

而本书重点讲述的对象是操作系统内核，它的主要组成部分包括：

1. 进程/线程管理：内核负责管理系统中的进程或线程，创建、销毁、调度和切换进程或线程。
2. 内存管理：内核负责管理系统的内存，分配和回收内存空间，并保证进程之间的内存隔离。
3. 文件系统：内核提供文件系统接口，负责管理存储设备上的文件和目录，并允许应用访问文件系统。
4. 网络通信：内核提供网络通信接口，负责管理网络连接并允许应用进行网络通信。
5. 设备驱动：内核提供设备驱动接口，负责管理硬件设备并允许应用和内核其他部分访问设备。
6. 同步互斥：内核负责协调多个进程或线程之间对共享资源的访问。同步功能主要用于解决进程或线程之间的协作问题，互斥功能主要用于解决进程或线程之间的竞争问题。
7. 系统调用接口：内核提供给应用程序访问系统服务的入口，应用程序通过系统调用接口调用操作系统提供的服务，如文件系统、网络通信、进程管理等。



## 操作系统接口

API（Application Programming Interface）：**API 是源代码层面的规则**，规定函数名、参数的类型与个数、返回值类型等。因此 API 是用来约束编译器 (Compiler) 的——编译器依据函数声明在编译期检查调用是否合法，而不合法的调用根本不会走到链接阶段。

ABI（Application Binary Interface）：**ABI 是机器码层面的规则**，主要包括基本数据类型的大小与对齐、通用寄存器的使用、参数与返回值的传递规则、以及堆栈的使用等等，是用来约束链接器 (Linker) 和汇编器 (Assembler) 的——只有双方遵循同一套 ABI，各自生成的机器码才能正确拼接、互相调用。

**系统调用**：是操作系统内核提供的**具体服务入口**。应用程序不能直接调用内核函数，必须通过特定的 ABI 约定来请求服务：把系统调用号放入约定的寄存器、把参数按约定放到寄存器或栈上，再执行一条特定的陷入指令（x86-64 的 `syscall`、RISC-V 的 `ecall`），由内核入口按调用号分发到对应服务函数。



下面列出了一些相对比较重要的操作系统接口或抽象，以及它们的大致功能：

- 进程（即程序运行过程）管理：复制当前进程创建子进程 fork 、退出进程 exit 、加载新程序并替换当前进程地址空间后执行 exec 等。
- 线程管理：线程（即程序的一个执行流）的创建、执行、调度切换等。
- 线程同步互斥的并发控制：互斥锁 mutex 、信号量 semaphore 、管程 monitor 、条件变量 condition variable 等。
- 进程间通信：管道 pipe 、信号 signal 、事件 event 等。（严格来说，signal 是异步通知机制，event 更常见于 Windows 的同步对象，二者属于广义的进程间通信）
- 虚存管理：内存空间映射 mmap 、调整堆（数据段）末尾位置以扩大或缩小堆的 sbrk 、共享内存 shm 等。
- 文件 I/O 操作：对存储设备中的文件进行读 read 、写 write 、打开 open 、关闭 close 等操作。
- 外设 I/O 操作：外设包括键盘、显示器、串口、磁盘、时钟 … ，主要采用文件 I/O 操作接口。



## 操作系统抽象

### 执行环境

**执行环境**：是应用程序正确运行所需的服务与管理环境，用来完成应用程序在运行时的数据与资源管理、应用程序的生存期等方面的处理，它定义了应用程序有权访问的其他数据或资源，并决定了应用程序的行为限制范围。

**普通控制流**：程序运行时以顺序、分支、循环以及多层嵌套函数调用等简单控制流组合的方式，一行一行地执行源代码（以编程语言级的视角），也是一条一条地执行汇编指令（以汇编语言级的视角）。

 **异常控制流**：在指令执行过程中，产生了执行环境的突变，前一条指令还在应用程序的代码段中，后一条指令就跑到操作系统的代码段中去了。典型情形包括中断/异常/陷入的处理，以及由内核发起的进程切换、信号处理等。

### 控制流上下文

这里我们把控制流在执行完某指令时的物理与虚拟资源内容，即确保下一时刻能继续 *正确* 执行控制流指令的资源内容称为控制流的 **上下文** (Context)

- 物理资源：即计算机硬件资源，如CPU的寄存器、可访问的物理内存等。
- 虚拟资源：即操作系统提供的资源，如文件，网络端口号，网络地址，信号等。



**异常控制流_中断**：**中断** (Interrupt) 是指由外部设备引起的外部 I/O 事件，如时钟中断、控制台中断等。外设中断是异步产生的，与当前正在执行的指令无关。产生中断后，操作系统需要进行中断处理来响应中断请求，这会破坏被打断前应用程序的控制流上下文，所以操作系统要保存与恢复被打断前应用程序的控制流上下文。

**异常控制流_异常**：**异常** (Exception) 是在处理器执行指令期间检测到的不正常或非法的内部事件（如 x86 平台上的除零错、地址访问越界）。需要注意并非所有异常都是程序错误：缺页异常、系统调用指令引发的陷入都属于正常且可恢复的情形。产生异常后，操作系统需要进行异常处理，这会破坏被打断前应用程序的控制流上下文，所以操作系统要保存与恢复被打断前应用程序的控制流上下文。

**异常控制流_陷入**：**陷入** (Trap) 是程序在执行过程中由于要通过系统调用请求操作系统服务而有意引发的事件。产生陷入后，操作系统需要执行系统调用服务来响应系统调用请求，这会破坏陷入前应用程序的控制流上下文，所以操作系统要保存与恢复陷入前应用程序的控制流上下文。

> 术语提醒：在 RISC-V 架构手册与 rCore 的后续实现中，中断与异常被统称为 **trap**（陷入），由 `stvec` 指向的统一入口分发处理；本节沿用教材的"中断/异常/陷入"三分法，目的是按事件来源区分，两者并不矛盾。



### 进程

一个进程是一个具有一定独立功能的程序在一个数据集合上的一次动态执行过程。操作系统中的进程管理需要采用某种调度策略将处理器资源分配给程序并在适当的时候回收，并且要尽可能充分利用处理器的硬件资源。



**进程上下文** – 一种控制流上下文。这里的进程上下文是指程序在运行中的各种物理/虚拟资源（寄存器、可访问的内存区域、打开的文件、信号等）的内容，特别是与程序执行相关的具体内容：内存中的代码和数据，栈、堆、当前执行的指令位置（程序计数器的内容）、当前执行时刻的各个通用寄存器中的值等。进程上下文如下图所示：

### 地址空间

**地址空间** (Address Space) 是对物理内存的虚拟化和抽象，也称虚存 (Virtual Memory)。它借助 CPU 中的内存管理单元 (MMU, Memory Management Unit) 硬件，为应用程序提供一个大的（可能超过计算机中的物理内存容量）、连续的（连续编址）、私有的（其他应用程序无法破坏）存储空间。

CPU 执行的每一次访存，其虚拟地址都要由 MMU 依据页表转换为物理地址；转换结果会缓存到 TLB 中以加速后续访问。



### 文件

**文件** (File) 主要用于对持久存储的抽象，并进一步扩展到为外设的抽象。

操作系统通过文件来屏蔽磁盘与内存差异，尽量以内存的读写方式来处理持久存储的数据。当处理器需要访问文件中的数据时，可通过操作系统把它们装入内存。文件管理的任务是有效地支持文件的存储、 检索和修改等操作。

## 操作系统特征

从总体上看，操作系统具有五个方面的特征：**虚拟化 (Virtualization)、并发 (Concurrency)、异步 (Asynchrony)、共享 (Sharing) 和持久 (Persistence)**。

- **虚拟化**：把一份物理资源变成多份逻辑资源（CPU 分时复用、内存分页），或把多份资源变成一份（如磁盘阵列）。
- **并发**：多个执行流在宏观上同时推进、微观上交替执行；并发不等于并行，单核上同样存在并发。
- **异步**：执行流的推进速度不可预知、随时可能被打断，因此共享资源的访问必须靠同步互斥机制来约束。
- **共享**：资源可被多个执行流共同访问，按方式分为互斥共享与同时共享。
- **持久**：数据在断电后依然保存在存储介质中，由文件系统提供抽象。
