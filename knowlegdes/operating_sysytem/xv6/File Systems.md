文件系统的目的是**组织和存储数据**。文件系统通常支持用户和应用程序之间的数据共享，以及持久性，以便在重新启动后数据仍然可用。

**他的主要实现目标如下：**

- 定义磁盘上的数据结构来表示目录和文件名称树，记录保存每个文件内容的块的标识，以及记录磁盘的哪些区域是空闲的
- 支持崩溃恢复，如果发生崩溃，文件系统必须重启后仍能够正常工作。风险在于崩溃可能会中断一系列更新，并使磁盘上的数据结构不一致（例如，一个块在某个文件中使用但同时仍被标记为空闲）。
- 不同的进程可能同时在文件系统上运行，因此文件系统代码必须协调以保持不变量。
- 访问磁盘的速度比访问内存慢几个数量级，因此文件系统必须保持常用块的内存缓存。

# xv6文件系统

## 层次结构

| **文件描述符（File descriptor）** |
| --------------------------------- |
| 路径名（Pathname）                |
| 目录（Directory）                 |
| 索引结点（Inode）                 |
| 日志（Logging）                   |
| 缓冲区高速缓存（Buffer cache）    |
| 磁盘（Disk）                      |

1. 文件描述符层使用文件系统接口抽象了许多Unix资源（例如，管道、设备、文件等）
2. 路径名层提供了分层路径名，并通过递归查找来解析它们。
3. 目录层将每个目录实现为一种特殊的索引结点，其内容是一系列目录项，每个目录项包含一个文件名和索引号。
4. 索引结点层提供单独的文件，每个文件表示为一个索引结点，其中包含唯一的索引号（i-number）和一些保存文件数据的块。
5. 日志记录层允许更高层在一次事务（transaction）中将更新包装到多个块，并确保在遇到崩溃时自动更新这些块（即，所有块都已更新或无更新）。
6. 缓冲区高速缓存层缓存磁盘块并同步对它们的访问，确保每次只有一个内核进程可以修改存储在任何特定块中的数据。
7. 磁盘层读取和写入virtio硬盘上的块。

不使用块0，他保存引导扇区。

块1称为**超级块**：它包含有关文件系统的元数据（文件系统大小（以块为单位）、数据块数、索引节点数和日志中的块数）。超级块由一个名为`mkfs`的单独的程序填充，该程序**构建初始文件系统。**

## 缓冲区缓存层

缓冲区就是**磁盘对应块在****内存中可供读取或修改的副本**。他的目的就是加快数据访问：

- 磁盘 I/O 通常是按**块（Block）**进行的，而进程读写内存是按**字节（Byte）**进行的。
- 进程从缓冲区里取数据，操作系统把数据攒够一个块再写进磁盘。它屏蔽了底层硬件的读写粒度，提供了统一的内存接口。

![img](https://cdn.nlark.com/yuque/0/2026/png/63601471/1788830140631-ecae5ed7-7138-4402-a3ac-f1da0b672adc.png)



Buffer cache层的作用是**同步对磁盘块的访问**和**缓存常用块**，代码在 kernel/bio.c中。

Buffer cache层对外暴露`bread`和`bwrite`两个接口，`bread`通过传入的设备号和块号，会调用`bget`检索对应的缓存区（若缓存未命中，则会寻找LRU缓冲区，将磁盘数据覆写到该缓冲区中），返回指向该缓冲区的指针。`bwrite`接口是将修改后的缓冲区写入磁盘对应的块，和`bread`相同都调用了`virtio_disk_rw(struct *buf, int)`对磁盘进行操作。

`brelse`释放缓冲区，每个缓冲区在被`bread`返回时会持有睡眠锁，在brelse中会释放该锁。

xv6的LRU是通过链表顺序实现的，最常使用的缓冲区在表头，反之就靠近表尾。他通过一个全局锁管理缓冲区双向链表，且需要严格维护链表顺序，并发性能差。



## 日志层

崩溃恢复往往是文件系统设计的关键问题，因为崩溃前后会使**磁盘上的文件系统处于不一致状态**。

xv6通过日志记录的方式解决崩溃问题，xv6系统调用不会直接写入磁盘上的文件系统数据结构。相反，它会在**磁盘上的*****log\*****（日志区）**中放置它希望进行的**所有磁盘写入的描述**。

一旦系统调用记录了它的所有写入操作，它就会向磁盘写入一条特殊的*commit*（提交）记录，表明日志包含一个完整的操作，xv6还会用**组提交策略**优化该过程。接下来系统调用将写操作复制到磁盘上的文件系统数据结构。完成这些写入后，**系统调用将擦除磁盘上的日志**。

如果系统崩溃，在执行任何进程之前，文件系统需要从崩溃中恢复。恢复代码会扫描磁盘上的日志区，如果日志标记为包含完整操作，则**恢复代码会将写操作复制到磁盘文件系统中它们所属的位置**。如果日志没有标记为包含完整操作，则**恢复代码将忽略该日志**。无论是上述哪种情况，恢复代码都会擦除日志。



**日志层设计：**

日志区位于超级块指定的固定位置，由**日志头块（Header Block）**和**日志数据块区（Logged Blocks）**组成。日志头块包含一个**扇区号数组**（每个logged block对应一个扇区号）以及**日志块的计数**。日志数据块区紧跟在头块之后，用于存放那些**被修改过的文件系统数据块的完整副本**。

日志系统可以将多个系统调用的写入累积到一个事务中，被称为**组提交（group commit）**。一次系统调用可能修改多个磁盘块，这些操作必须被分配到同一个事物中，所以组提交会发生在没有系统调用的情况下进行。

日志空间是有限的，会导致两个问题。第一，如果一个写操作会更改大量磁盘块，超过**日志空间容量logsize**，如`write`，xv6会将大的写入分解为多的小的写入。`unlink`删除操作会涉及大量数据块，位图块和inode块的修改，但xv6整个磁盘的位图管理仅仅使用了一个位图块，巧妙避免了该问题。第二，在执行系统调用前，必须进行严格的**日志空间预检**，确保剩余空间能满足写入操作。



**日志层代码：**

日志区数据结构的定义

`outstanding`是**正在执行的文件系统系统调用数**，`MAXOPBLOCK`是**一次系统调用所能使用的最大日志块数**，可见xv6对于日志空间预检是非常保守的。

首先对日志加锁，进入一个死循环。如果当前日志区为`committing`状态就睡眠。如果日志区容量不足，即已使用的日志块数量`log.lh.n` + 预申请日志块数量`outsanding * MAXOPBLOCKS` > 日志块总数量`LOGSIZE`就睡眠。如果空间足够，将`outstanding+1`，释放锁，退出循环。

`log_write`充当`bwrite`的代理。

它将块的扇区号记录在内存中，在磁盘上的日志中预定一个槽位，并调用`bpin`将缓存固定在block cache中，以防止block cache将其逐出。block cache就是**buffer cache层的bcache**，`bpin`通过增加该缓冲区的引用计数来防止其被RLU机制淘汰。日志头块和日志数据块也会在block cache中有一个副本。

他遍历日志块的方式比较巧妙，首先寻找是否有被多次修改的磁盘块，其已经有了槽位无需向日志区再添加一次，这种优化称为合并（absorption）。如果没找到，就自然遍历到最后，那么就需要添加一个新槽位。

![img](https://cdn.nlark.com/yuque/0/2026/png/63601471/1788917921937-d1cf7ab0-7be2-46b9-8aac-a98f39bfa0f6.png)



`end_op`在文件系统调用结束后使用。

首先创建一个`do_commit`标志位。对日志区加锁，减少正在执行的系统调用数`log.outstanding - 1`，如果此时没有任何系统调用执行，就设置`do_commit`标志位和`log.committing`为1，如果`outstanding`不为0，尝试唤醒因空间不足而睡眠的`begin_op`。

释放日志锁，进入`commit`环节，调用`commit()`。调用完成后设置`log.commiting`为0，唤醒睡眠的`begin_op`

## 块分配器

**位图的概念：**

xv6文件系统通过**位图**统计磁盘块的使用情况，区分哪些块是空闲的，哪些块正被使用。该数据结构的每个bit位，都对应一个磁盘块，**如果该位是**`**1**`**代表已占用，如果是**`**0**`**代表空闲。**

xv6在磁盘中预留了一些块来存储位图，由于磁盘块很多，位图通常占据磁盘上连续的多个块。



**块分配器代码：**

`bzero`作用是将一个磁盘块清0。首先在磁盘或Block Cache中读取块的数据到缓存，调用`memset`清0，再调用`log_write`将该块的缓存预写入日志区，最后调用`brelse()`释放缓冲区。

![img](https://cdn.nlark.com/yuque/0/2026/png/63601471/1788924378671-5aea8580-8212-40cc-803c-cb37fdeb19c0.png)



`balloc`作用是分配一个新的磁盘块。

```c
// Allocate a zeroed disk block.
static uint
balloc(uint dev)
{
  int b, bi, m;
  struct buf *bp;

  bp = 0;
    //遍历所有的位图块，BPB是每个位图块的长度（bits）
  for(b = 0; b < sb.size; b += BPB){
      //将该位图块从磁盘读到缓冲区bp
    bp = bread(dev, BBLOCK(b, sb));
      //本循环遍历该位图块的每bit位
      // bi既要小于一个位图块的最大容量BPB，还要小于文件系统对磁盘分的总块数
    for(bi = 0; bi < BPB && b + bi < sb.size; bi++){
      m = 1 << (bi % 8); //生成掩码，用来核对块的状态
      //bp->data是字节数组（uchar[]类型）
        if((bp->data[bi/8] & m) == 0){  //判断某磁盘块是否空闲
        bp->data[bi/8] |= m;  //若空闲，改变位图该bit状态为1
        log_write(bp); //告诉内核该磁盘块需要写入日志区
        brelse(bp);
        bzero(dev, b + bi);	//将该磁盘块清0
        return b + bi;	//返回分配的位置
      }
    }
    brelse(bp);
  }
  panic("balloc: out of blocks");
}
```



`bfree`释放一个磁盘块，就是在位图上将对应的bit修改为0

## 索引节点层

`inode`即索引节点，指的是磁**盘上的数据结构**`**struct dinode**`或**内存中的**`**struct inode**`**副本**。用于存储文件或目录的元数据，帮助操作系统识别和管理文件。

**多个文件名（硬链接）指向同一个 inode，且硬链接的文件，只是文件名不同，他们存储的物理地址相同。所以更改会同步到所有文件上。**

磁盘上的inode都被打包到一个称为inode块的连续磁盘区域中，每个inode的大小都相同。在给定`i-number`的情况下很容易找到对应的节点。

磁盘上的inode由`struct dinode`（***kernel/fs.h***:32）定义。字段`type`标识文件类型，区分文件、目录和特殊文件（设备）。`type`为零表示磁盘inode是空闲的。字段`nlink`统计引用此inode的目录条目数，以便识别何时应释放磁盘上的inode及其数据块。字段`size`记录文件中内容的字节数。`addrs`数组（指针数组）记录保存文件内容的磁盘块的块号。

内存中的inode结构体，只有当c指针指向某个inode，才会在内存维护该inode的副本。最重要的是引用计数`ref`，`iget`和`iput`会修改引用计数返回指向该节点的指针，且只要引用计数不为0，内存就不会释放该索引节点副本。

xv6文件系统的inode有四种锁或类似锁的结构

inode缓存是直写的，这意味着修改已缓存inode的代码必须立即使用`iupdate`将其写入磁盘。

## 目录层

目录数据结构，包含目录名和`i-number`编号，在inode中目录文件类型为`T_DIR`

![img](https://cdn.nlark.com/yuque/0/2026/png/63601471/1789196708902-eddeafa2-7655-4048-a1b0-298966112aa9.png)



`lookdirup`在目录中**查找对应名称的条目**，如果`dirlookup`找到具有正确名称的条目，它将更新`*poff`并返回通过`iget`获得的**未锁定的inode**。

返回未锁定的inode的原因是，避免锁重入和加锁顺序不同导致的死锁。因为有 `.`和`..`的存在，这种情况可能发生。

![img](https://cdn.nlark.com/yuque/0/2026/png/63601471/1789197573875-b1ebc7f6-71c0-4f14-881e-56d08a68a42e.png)



`dirlink`将给定名称和inode编号的新目录条目写入目录`dp`。如果名称已经存在，`dirlink`将返回一个错误。如果找到一个空的目录项，则修改该目录项并调用`writei`写回磁盘。即使没找到空闲的，也会在off（此时`off == dp->size`）处覆写并写回的。

![img](https://cdn.nlark.com/yuque/0/2026/png/63601471/1789198927464-eccc442b-6b40-4a01-875d-ef1cf9c5ef4f.png)



## 路径名

`namei`函数返回路径指向元素的节点指针，`nameiparent`返回该元素父目录的节点指针。

他们都调用了`namex`这个核心函数

![img](https://cdn.nlark.com/yuque/0/2026/png/63601471/1789200053564-2a936be6-0c1d-46dd-b649-875e967e9b58.png)



`namex`是一个从父目录向子目录一步步遍历寻找的过程。

如果路径以`/`开始，就从根路径开始寻找，否则从当前工作目录开始寻找。在while循环中`skipelem`每次取出path中最靠前的目录名再将path推后一层，循环内会先调用`ilock`将父目录锁住，再使用`dirlookup`寻找子目录，在循环结束前`iunlockput`对父目录解锁，直到找到最后的目录，返回该节点的指针。

这里更体现了dirlookup不加锁返回的优点，由我们自己安排锁序，避免死锁问题

![img](https://cdn.nlark.com/yuque/0/2026/png/63601471/1789200373906-5437fe0a-675e-4f3e-86f5-06ea7851ee5d.png)

# 对磁盘和内存读写之间的理解

对于裸机，c语言通过指针修改的就是**真实的内存物理地址**，CPU 就会**直接在物理总线上发起读写操作**。

CPU 只认一个**统一的物理地址空间**。在这个空间里，RAM、Flash 以及外设寄存器（如 UART、GPIO）都被**映射到了特定的物理地址**上。

裸机上的内存（如 RAM、Flash、ROM）是实实在在存在的电子元件。RAM 用于在运行时保存变量、堆栈等易失性数据，而 Flash/ROM 用于永久保存程序代码。



有操作系统的现代计算机，因为**MMU（内存映射）机制**的存在，C语言的指针操作的是**虚拟地址**，MMU模块会负责将其翻译为真实的物理地址。为了保持安全性和隔离性，用户程序不应直接访问磁盘，而是通过文件系统提供的上层接口（如`read`，`write`）来间接访问。

现代计算机使用DMA（直接内存访问）的方式，直接将数据由硬盘搬运至内存，无需cpu干预。



无论是裸机还是现代计算机，cpu都不能直接读取磁盘数据。`磁盘->内存->cpu缓存->cpu`的模式是一定的，且需要cpu的参与。
