面向对象语言通过函数对象实现回调，类C语言通过函数指针实现回调。

**回调的目的：**

1. **解耦**：主逻辑和具体的处理逻辑分离，比如一个 “排序函数” 可以通过回调适配不同的排序规则（升序 / 降序 / 按自定义规则）；
2. **异步处理**：处理耗时操作（如网络请求、文件读写）时，不用阻塞等待，而是指定 “完成后要执行的回调函数”，操作完成后自动调用；
3. **定制化逻辑**：让通用函数支持自定义行为，比如 C 标准库的 `qsort`（快速排序）就是通过回调实现任意类型数据的排序。

#### select实现原理

**实现原理：**

1.**监听集合fdset**，**处于用户态**，本质是一个**位图**（桶排序数组），数组大小为1024bit（1024 Byte/8*sizeof(long)）当需要监听某个文件描述符时，将其对应的元素置为1，其他为0。

2.nfds = fd_max + 1他会在0~fds - 1（左闭右开）,会遍历该范围，监听的文件描述符中有一个就绪了，将其置为1，**返回给内核态，**此时变为**就绪集合。**

3.用FD_ISSET和就绪集合中的文件描述符进行比对，实现了IO多路复用。

**缺点：**

1. 监听和就绪混杂了
2. 文件数固定
3. 大量用户态和内核态的拷贝
4. 找就绪态浪费时间

  

### 补充：缓冲区

#### 一、标准输入缓冲区的核心定义

标准输入缓冲区（也叫 `stdin` 缓冲区）是**C 标准库（如 glibc）在用户空间为标准输入流（**`**stdin**`**）分配的一块连续内存**，它不属于内核，而是进程自己的内存区域。

- 它的直接管理者是 `FILE` 结构体（`stdin` 指向的就是这个结构体），结构体里会记录缓冲区的起始地址、当前读取位置、缓冲区大小等信息；
- 它的默认类型是「行缓冲」，这也是新手最容易踩坑的特性。

#### 二、为什么需要这个缓冲区？（核心作用）

没有缓冲区的话，`scanf` 每读一个字符都要发起一次 `read` 系统调用（从内核读取键盘数据），而系统调用会触发「用户态 ↔ 内核态」的切换，开销很大。

**fork实现的底层原理**

**上半部（不可中断，时间短）**

1. 拷贝一份父进程的task struct
2. 修改至子进程的必要信息

**下半部（时间长）**

3. 将子进程的task struct 压入就绪队列

**写时复制 COW**

父子进程一开始**共享虚拟地址到物理内存的映射**，当父子进程出现写行为时，才需要分配到物理内存。

  

#### fork的拷贝

**定义的全局变量存储在程序段中**，**函数中定义的变量存储在栈上，malloc申请的变量存储在堆上。**

在逻辑上，用户态中是拷贝的，某一进程在用户态的更改不会影响另一个进程。文件流也是拷贝，但要注意行缓冲机制。

**重点：内核态中父子进程对于文件对象是共享的。**

所有有关fork的笔试题，应该将代码段和pc指针画出来，记住fork的拷贝是完全拷贝，只有**执行完fork才会执行之后的代码**，拷贝完会同步执行。

#### 竞争条件

两个进程并发访问共享资源，在一个进程完成操作前就触发时钟中断，写入没完成，另一进程就对内存中未更改的数据进行操作，导致结果不正确的现象。

#### 虚拟内存和物理内存的转换

**页表**

虚拟页大小是固定的，4096 = 2的12次方。描述虚拟页中内存地址一共有32位，前20位固定，后12位大小不固定，称为**页内偏移**。在与物理页转换时，后12位相对关系不变，仅前20位需要转换。

构建一个长度为2的20次方的数组，数组元素存储物理页号和控制信息占4B，整个数组大小为4MB，称为**页表**。

**局部性原理**

通过页表分级，前十个页号找页目录表，目录表指向另一个页表，配合后十位，在页表中找到需要的物理信息。将一个4MB大小的页表，转换成2个4kb大小的信息。

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1770780012736-a2c42036-d358-4f2d-a2b0-4e9ec90d695b.png)

对于x86_64系统，前16位不用+**36位（4个9位进行分级）+后12位 = 48位 ， 有256TB的虚拟内存大小，**内核态、用户态各占一半。

对于不同进程，虚拟页到物理页的映射关系不同，进程切换的代价：切换上下文，切换页表，对于fork，cow未写入时，父子进程共用一个页表，**写入操作触发缺页异常。**

**signum**参数，可以通过查阅信号表获得

#### 阻塞和未决实现原理

阻塞：让产生的信号，不能马上递送，而是处于未决状态。

未决：已产生但未递送的信号。

在**已有信号传递过程中**产生的信号使用**位图（用bit位保存信息）**存储**pending**信息，重复的信号只会被存储一次，待传递完后才能继续执行。

发送的**不同信号**想栈一样被存储，执行。但同种信号只能有一个处于传递过程中，其他都处在未决态，被阻塞。

#### 低速系统调用

即可能产生**永久等待**的系统调用，在信号传递完成之前，低速系统调用会重启。

#### signal函数的特点

1. 一次注册永久有效
2. 传递A时，将A信号加入mask，重复信号存储到pending
3. 会自动重启低速系统调用

# 线程概念

线程是一个正在执行的程序，是轻量级的进程，多线程并发执行。

同一个进程存在多个线程，**多个线程共享内存资源（堆，代码段和数据段）**。

每个线程有自己单独的栈，上下文，task_struct。

用户级线程： cpu调度由**进程**处理

内核级线程： cpu调度由**操作系统处理**

**cpu调度以线程为单位**，之前写的进程可以看作**单线程进程。(内存资源分配还是以进程为单位)**

在linux操作系统中，每一个进程和线程都有自己独立的task_struct。

**特点：**

- 减小上下文切换的代价
- 不需要页表切换
- 线程间共享内存，方便通信

# 线程的并发和共享

在多线程中，**perror函数是不能使用的，**而是使用**返回值的数值（整形）**

**perror使用条件：**

1. return -1或特定形式返回值
2. 修改全局变量errno

在多线程中，对数据段的访问是共享的，不知道谁修改了errno

利用**strerror函数**定义一个新的报错检测宏

数据段共享：对全局变量的更改会同步到所有线程中。

堆空间共享：如malloc函数申请堆空间，将指针传递到子线程中。（pthread_create函数多少个参数很灵活）

# 线程的取消

线程的共享特征导致不能使用信号控制，因为不知道该信号是由那个线程发送的。

使用pthread_cancel函数向另一个线程**发送取消请求**。

不会立即终止线程，而是**将取消标志位置为1**，待该线程运行到**取消点（特殊函数）**时（大多是之前，printf是之后），终止线程，返回-1，这是一个**异步操作**。

# 资源清理

线程终止的异步性会导致**内存泄漏，**因为不知道申请了多少资源和申请的资源是否在线程终止前就被释放了**。**

**资源清理栈：**

每种**资源申请**操作都对应着一种**释放行为**，资源清理栈保证**申请了多少资源就释放多少资源**。在线程终止时，会将栈清空。

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1771918547926-d42ee185-b46a-493e-899f-97ce29c58d26.png)

通过将资源清理函数包装成void*为参数的函数，即可调用资源清理栈。

注意：只有**pthread_exit(NULL)和pthread_cancel终止的线程**才会调用资源清理函数。

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1771980821482-ddb8fb2b-487b-4ac8-8ddb-04bca231b5aa.png)

**代码层面的原因，pop和push必须在同一个作用域中成对出现。有了pop就不要手动清理内存。**

# 死锁

线程阻塞，等待永远不可能的条件成立。

**死锁出现的原因：**

1. 申请多个资源顺序有问题
2. 持有锁的线程终止了

在由线程终止的任何分支前都要解锁，倘若线程可能被cancel，那么加锁后立刻就解锁。**（pthread_mutex_lock不是取消点）**

3. 同一个线程对锁加锁两次

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1771985739261-d445ebff-b7c4-4d05-a0d6-879057f1cdd5.png)

若主动终止，在终止前将所有锁解除。

若cancel，每次加锁后马上将解锁行为压入栈中。

# 条件变量

实现**无竞争的同步**

设计一个条件，这个条件决定了本线程是否等待

如果不满足，调用wait使本线程陷入等待

此时，另外线程运行，直到讲条件改成满足，通知（signal）阻塞的线程恢复就绪.

一般主线程分配任务，子线程执行任务，有先后顺序。

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1772351481896-4e8149a1-bf01-402c-bd73-e81e34a59c7b.png)

**条件变量要配合锁来使用**，目的是**让状态检查和陷入等待是一个原子操作**。

**pthread_cond_wait的内部实现（重要）**

**前半**

1. 判断有没有加锁
2. 把自己加入唤醒队列
3. 解锁并陷入等待（原子）

**后半**

1. 就绪
2. 加锁
3. 持有锁之后继续运行

pthread_cond_wait内部有一个锁
