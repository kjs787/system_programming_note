## 传输层 TCP

**可靠性**

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1772590211386-974d1f70-d8aa-4494-b957-7c6ba2c6b4dc.png)

2. 缓冲区保存已发送但未确认的数据

### select的缺陷

1. fd_set的本质是位图，容量固定1024（扩容要改内核，很困难）
2. 监听和就绪使用同一个数据结构，很麻烦
3. 存在多次大量从用户态到内核态的拷贝
4. 采用**轮询**找到就绪的FD（海量连接少量就绪时十分耗时）

# 进程池

## **设计架构**

1. 高性能 充分利用操作系统提供的资源
2. 可维护性——>抽象 （过早优化是万恶之源）

- 基于线程，每有一个客户端连接时，创建一个线程；断开时，销毁。有很高的可维护性，但性能差，浪费大量资源创建和销毁线程。

  

### 池化的思路

申请了资源之后，用完后不马上回收，可以交给其他事情复用。

**进程池/线程池设计思路：**

1. 提前创建若干个进程
2. 每当有任务到来，分配一个进程
3. 任务完成后归还进程
4. 整个进程池关闭时再销毁

**事件驱动模型(event-driven)：**

sha1sum 文件名

md5sum 文件名

# 线程池

进程池的（Nignx，Chrome）：

优点：一个子进程崩溃，不影响其他子进程

缺点：进程间通信困难，需要消耗很多资源

## 线程池的架构

用任务队列实现生产者，消费者

进程池通过阻塞实现同步，线程池通过互斥锁和条件变量实现同步。

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1774057327260-f4cd9fc4-ba42-44c9-ad82-57b958f27731.png)

## 线程池的退出

  

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1774063100108-71869c39-31b0-4c5c-95fc-9bdc68b7aba2.png)

多线程不能通过接收信号来进行退出，那么先fork一个子进程，让主进程接收信号通过管道发给子进程，子进程是多线程的逻辑，负责关闭所有子线程，退出。
