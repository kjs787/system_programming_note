**回调（call back）: 把函数作为参数传给另一个函数，在合适的时机被调用。**

面向对象语言通过函数对象实现回调，类C语言通过函数指针实现回调。

**回调的目的：**

1. **解耦**：主逻辑和具体的处理逻辑分离，比如一个 “排序函数” 可以通过回调适配不同的排序规则（升序 / 降序 / 按自定义规则）；
2. **异步处理**：处理耗时操作（如网络请求、文件读写）时，不用阻塞等待，而是指定 “完成后要执行的回调函数”，操作完成后自动调用；
3. **定制化逻辑**：让通用函数支持自定义行为，比如 C 标准库的 `qsort`（快速排序）就是通过回调实现任意类型数据的排序。

#### select实现原理

**实现原理：**

1.**监听集合fdset**，**处于用户态**，本质是一个**位图**（桶排序数组），数组大小为1024bit（1024 Byte/8*sizeof(long)）当需要监听某个文件描述符时，将其对应的元素置为1，其他为0。

2.nfds = fd_max + 1他会在0~fds - 1（左闭右开）,会遍历该范围，监听的文件描述符中有一个就绪了，将其置为1，**返回给内核态，**此时变为**就绪集合。**

3.用FD_ISSET和就绪集合中的文件描述符进行比对，实现了IO多路复用。

**缺点：**

1. 监听和就绪混杂了
2. 文件数固定
3. 大量用户态和内核态的拷贝
4. 找就绪态浪费时间

  

### 补充：缓冲区

#### 一、标准输入缓冲区的核心定义

标准输入缓冲区（也叫 `stdin` 缓冲区）是**C 标准库（如 glibc）在用户空间为标准输入流（**`**stdin**`**）分配的一块连续内存**，它不属于内核，而是进程自己的内存区域。

- 它的直接管理者是 `FILE` 结构体（`stdin` 指向的就是这个结构体），结构体里会记录缓冲区的起始地址、当前读取位置、缓冲区大小等信息；
- 它的默认类型是「行缓冲」，这也是新手最容易踩坑的特性。

#### 二、为什么需要这个缓冲区？（核心作用）

没有缓冲区的话，`scanf` 每读一个字符都要发起一次 `read` 系统调用（从内核读取键盘数据），而系统调用会触发「用户态 ↔ 内核态」的切换，开销很大。
