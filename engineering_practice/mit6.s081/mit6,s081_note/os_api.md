# 什么是操作系统？

最接近硬件的软件， 负责分配系统资源和抽象底层硬件。

一个优秀的操作系统应该具备这些功能：

- 抽象硬件
- 共享硬件资源
- 隔离性（Isolation）
- 数据共享，必要时不共享(Access Control)
- 高性能
- 多用户场景

操作系统设计是困难的，矛盾的，正因如此又是有趣的。

# 用户态和内核态

**用户态（Userspace）**会运行各种应用程序，如文本编辑器(VI)，c语言编译器(CC)，终端命令行(shell)

**内核态（Kernel）**，内核程序kernel是开机后第一个被启动的程序。Kernel程序只有一个，它维护数据来**管理每一个用户空间进程**。Kernel同时还维护了大量的数据结构来帮助它**管理各种各样的硬件资源**，以供用户空间的程序使用。

- kernel会维护文件系统和进程管理系统，还会提供各类其他的服务。
- 用户空间的程序会与内核中的文件系统交互，文件系统再与磁盘交互。
- 内核更像是一种环境，他不是某一个进程，没有实体。内核永远特权，永远掌控全局。

# 文件IO

类unix操作系统使用**文件描述符 fd**，对文件（文件，设备，管道）进行抽象。

文件描述符是一个小整形集合，其中 **标准输入 0 ，标准输出 1，标准错误输出 2** 已经被占用了，但你仍能方便的对其进行重定向 。

常用的系统调用是 **open 和 write , read** 。其中open会返会一个fd，你还可以限制其读写行为。

write和read可以在文件中读写数据，他们不在用户态缓冲，被称为不带缓冲的文件IO。

其中 fork和exec分离的设计让文件重定向更加自由，exec会**保持父进程已打开的文件描述符。**你可以使用系统调用dup可以复制一个已打开的文件描述符

  

# 管道

管道是一对共享的文件描述符，使用系统调用pipe()实现，将一对文件描述符分配到长度为2的整形数组中。

在fork后，父子进程各关闭管道的一端，利用另一端进行读写，建议用宏定义预设读写端，防止出错。

shell用管道和重定向实现了如下操作：

# 文件系统

目录形成一个树，从一个叫根的特殊目录进行伸展，通过chdir()系统调用，可以改变当前工作目录。

还有创建新文件和目录的系统调用：

- `mkdir`创建一个新目录
- `open`中若使用`O_CREATE`标志将会创建一个新的数据文件
- `mknod`创建一个新的设备文件

我们想**获取目录/文件属性**，使用系统调用 **fstat()** ,他会将信息存储在struct stat类型的结构体中：

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1780921406061-93d79e55-49ff-48a4-b1cb-485c7c544c86.png)

对文件的操作在 ls.c 中被大量使用

文件名是可以重复的，不同文件名可以指向相同的文件。使用 **link() 和 ulink()** 系统调用为文件增删连接。

一个例外是`cd`，它是内置在shell(_**user/sh.c**_:160)。`cd`必须更改shell本身的当前工作目录。如果`cd`作为常规命令运行，那么shell将分出一个子进程，子进程将运行`cd`，`cd`将更改子进程的工作目录。父目录(即shell的)的工作目录不会改变。
