**页表**在硬件中通过**处理器**和**内存管理单元 MMU**（Memory Management Unit）实现，MMU会根据cpu提供的虚拟地址和内存中的地址关系表单对照，找到真实物理地址。在RISC-V上一个叫做SATP的寄存器会保存表单所在地址，SATP寄存器由内核维护。

当进程切换时，SATP的内容也要切换，这样不同的程序对应的物理地址就是隔离的。

  

# 虚拟地址到物理地址的转换

指令只使用虚拟地址，**分页硬件（paging hardware）**将其转换为物理地址，然后将其发送到**DRAM硬件**来进行读写。

xv6仅用**64位中的后39位，作为虚拟地址（由index + offset组成）**。RISCV的页表，在逻辑上仅是2的27次方的**页表条目（PTE : Page Table Entry）**，**PTE是由PPN+标志位**组成，通过分页硬件，将**物理页号PNN + 偏移offset** 拼接起来，就组成了物理地址。

每个**PTE包含标志位**，这些标志位告诉分页硬件**允许如何使用关联的虚拟地址**

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1781244709501-870952d0-5460-45fb-a6ce-562dbcce079c.png)

  

## 页表分级

实际情况下，xv6页表通过多级页表索引，每一级页表目录有512个PTE条目（正好4096个字节）。这种方式**减少页表占用的物理内存，还可以使分配给页表的内物理存不必连续**。

且如果最高级的PTE为空，那么他的中间级和最低级可以不映射，这变相减少了页表条目的数量。

对多级页表的**检索使用的都是物理地址**，最高级页表的物理地址从寄存器：SATP 获取，次级是前一级的PTE中获取

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1781245215136-29bb6efc-ddb0-49b7-8c1b-38b418b78fcd.png)

上图是PTE中的一些标志位

- 第一个标志位是Valid。如果Valid bit位为1，那么表明这是一条合法的PTE，你可以用它来做地址翻译。
- 下两个标志位分别是Readable和Writable。表明你是否可以读/写这个page。
- Executable表明你可以从这个page执行指令。
- User表明这个page可以被运行在用户空间的进程访问。
- 其他标志位并不是那么重要，他们偶尔会出现，前面5个是重要的标志位。

  

# XV6地址映射

## 区分虚拟地址和页表

**虚拟地址VA**是一套映射关系，没有实物，应用程序可以通过该逻辑读写物理内存，每个进程可以将虚拟地址映射为不同的物理地址。

**页表pagetable**是存储虚拟地址到物理地址映射关系的表单，表单的元素是PTE。他是实物，必须在内存中申请物理空间进行存储。MMU通过查表，就可以将虚拟地址转换为**物理地址PA**

  

RISC-V Sv39 分页把 64 位虚拟地址拆成**两大部分**：**用户虚拟地址段 + 内核虚拟地址**

1. **用户虚拟地址（0 ~ MAXVA）** 对应第二张图，**进程私有**，仅用户态可访问； 每个进程页表各自映射自己的 text/heap/stack，进程切换时这部分映射全部更换。
2. **内核虚拟地址（KERNBASE 及以上 + MMIO 外设区）** 对应第一张图，**全局共享**，仅内核态可访问； 所有进程共享内核页表，进程切换时不需要修改这部分页表项。

虚拟地址空间一共512G，3级的512项PTE页表可以实现全覆盖。实际大多数的页不会被存储为PTE，所以页表空间是完全够用的。

## 内核虚拟地址

从KERNBASE ~ PHYSTOP这块区域：存放内核本身、提供所有动态内存分配、承载进程内核栈，是操作系统内存管理核心区域。

我们注意到**内核虚拟是直接映射**的，这种分配方式会带来诸多便利。

**kernbase**（0x80000000）下方的虚拟地址全部用于**映射硬件外设** 。

**内核栈的作用：**

内核栈会在进行用户态到内核态转换时调用，保存内核上下文（寄存器状态，内核调用栈）。内核运行系统调用时的一些临时变量，函数返回结果，都要存储在内核栈。每个进程都会被分配固定大小的内核栈，再将其物理地址映射到内核页表的高地址区域，让内核帮忙维护。（参考proc.c中的procinit代码，在系统booting时让所有进程都的内核栈都映射完成了）

  

**IO设备：**

- PLIC是中断控制器（Platform-Level Interrupt Controller）。用户虚拟地址区不应超过该部分。
- CLINT（Core Local Interruptor）也是中断的一部分。所以多个设备都能产生中断，需要中断控制器来将这些中断路由到合适的处理函数。
- UART0（Universal Asynchronous Receiver/Transmitter）负责与Console和显示器交互。
- VIRTIO disk，与磁盘进行交互。

  

  

## 用户虚拟地址

当进程向xv6请求更多的用户内存时，xv6首先**使用**`**kalloc**`**来分配物理页面**。然后，**它将PTE添加到进程的页表中**，指向新的物理页面，同时**更新标志位**。大多数进程不使用整个用户地址空间；xv6在未使用的PTE中留空`PTE_V`。

xv6在栈正下方放置了一个**无效的保护页（guard page）**。如果用户栈溢出并且进程试图使用栈下方的地址，那么由于映射无效（`PTE_V`为0）**硬件将生成一个页面故障异常（Page Fault）**。

## 以页为单位的PTE映射

硬件最小操作单位是**整页：4096字节**，该页内的虚拟地址只要映射成页首的虚拟地址，存储为PTE即可。 软件只负责建立页首之间的映射，页内偏移由硬件自动拼接，不会错位。

- 这解释了为何我们需要像PGROUNDDOWN这样的宏来对齐页首

  

同一个虚拟页，它在三级页表中的数组下标（PTE 存储槽位）**永久固定**，和映射的物理页位置无关。且用户虚拟地址的PTE天然小于内核地址的PTE。不难推测出，共享的内核页表低位PTE完全没有被映射。

  

**pagetable_t** 存储的就是页表物理地址，内核利用线性物理映射，以虚拟地址形式（数组）访问对应物理页表内存。

  

# 页表缓存TLB

抽象带来操作的灵活性

三次内存读取的代价太大，几乎所有的处理器都会对于最近使用过的虚拟地址的翻译结果有缓存。这个缓存被称为：**Translation Lookside Buffer**

page table是一个无比强大的机制，他提供了内存系统的一层抽象，为操作系统提供了非常大的灵活性。
