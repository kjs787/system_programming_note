# 调用与栈帧

## 指令集架构

**risc-v，arm，x86 都是ISA(****Instruction Sets Architecture****)**，被翻译为**指令集架构**。每种处理器都关联一种ISA，每一条指令都有一个对应的二进制编码或者一个操作码Opcode，当处理器看到这些编码，就知道执行什么操作。

risc-v，arm属于**精简指令集架构(RISC)**，而x86-64属于**复杂指令集架构(CISC)**，RISC的特点是指令数量少，执行操作单一、简单、速度快，且是开源的。

x86指令集架构的指令数量超过了15000，且以每个月3个的数量在增长。Intel并没有下线任何指令且特别重视向后兼容，所以一个现代的Intel处理器还可以运行30/40年前的指令。

  

## Risc-v寄存器

寄存器是cpu或存储器上，预先定义可以存储数据的地方。

汇编代码操作的对象就是寄存器，这往往是进行运算和读取数据最快的方式。

在汇编代码中，我们会使用ABI name。第一列的寄存器名字只会用在RISC-V的Compressed Instruction中。

第四列的saver的区别是，**callee saved寄存器在函数调用时会保存（不被重写），caller saved寄存器在函数调用时不保存。**

## Risc-v栈

Risc-v栈会从高地址向低地址伸展。每一次我们调用一个函数，函数都会为自己创建一个**栈帧Stack Frame**，并且只给自己用。函数通过移动Stack Pointer来完成Stack Frame的空间分配。

**SP（Stack Pointer）指向栈顶和FP（Frame Pointer）指向栈底**，是两个重要的寄存器。

SP标志着栈帧在栈的位置，通过对SP做减法，可以为下一个栈帧预留空间，同样对SP做加法可以删除栈帧；

FP通过寻址，可以方便的访问 RA 和 fp 的重要数据（他们每个占用8字节/64bit = uint64）。

可以使用gdb定位栈帧，并使用info frame指令来观察栈帧的信息

# 陷入

## RV陷入机制

在RV处理陷入时，会执行许多重要寄存器写入操作，内核可以读取这些寄存器来明确已经发生的陷入。

以下是陷入处理中重要的寄存器：

- `stvec`：内核在这里写入其陷阱处理程序的地址；RISC-V跳转到这里处理陷阱。
- `sepc`：当发生陷阱时，RISC-V会在这里保存程序计数器`pc`（因为`pc`会被`stvec`覆盖）。`sret`指令会将`sepc`复制到`pc`。内核可以写入`sepc`来控制`sret`的去向。
- `scause`： RISC-V在这里放置一个描述陷阱原因的数字。
- `sscratch`：内核在这里放置了一个值，这个值在陷阱处理程序一开始就会派上用场。
- `sstatus`：其中的**SIE**位控制设备中断是否启用。如果内核清空**SIE**，RISC-V将推迟设备中断，直到内核重新设置**SIE**。**SPP**位指示陷阱是来自用户模式还是管理模式，并**控制**`**sret**`**返回的模式**。

  

当需要强制执行陷阱时，RISC-V硬件对所有陷阱类型（计时器中断除外）执行以下操作：

1. 如果陷阱是设备中断，并且状态**SIE**位被清空，则不执行以下任何操作。
2. 清除**SIE**以禁用中断。
3. 将`pc`复制到`sepc`-》中断返回的地址
4. 将当前模式（用户或管理）保存在状态的**SPP**位中。
5. 设置`scause`以反映产生陷阱的原因。
6. 将模式设置为管理模式。
7. 将`stvec`复制到`pc`。
8. 在新的`pc`上开始执行。

CPU不会切换到内核页表，不会切换到内核栈，也不会保存除`pc`之外的任何寄存器。内核软件必须执行这些任务。

## 从用户空间的陷入

用户程序发出系统调用（`ecall`指令），或者做了一些非法的事情，或者设备中断，那么在用户空间中执行时就可能会产生陷阱。用户态的陷入更危险，因为satp寄存器指向用户页表，栈指针可能包含无效甚至恶意的值。

  

首先了解**uservec（kernel/uservec.S）**，一段汇编代码，**是用户态陷入时cpu跳转到的第一条代码**，他被映射到蹦床页面trampoline的区域，内核页表和用户页表都可以访问。

他的作用是：

1. **保存中断时所有通用寄存器状态到trapframe**
2. 切换用户页表到内核页表
3. 切换用户栈到内核栈
4. 执行usertrap陷入处理函数
5. 返回执行userret函数，切换回用户态

**RV通过sscratch寄存器在用户态提供安全临时缓存** 。sscratch寄存器预先存放指向当前进程的Trapframe Page的基地址指针，在陷入发生时，**sscratch会和a0寄存器交换数据**，因为我们需要保存a0的值，但不能对其他通用寄存器做任何操作，之后使用a0作为trapframe基地址指针存储所有寄存器的值。

![](https://cdn.nlark.com/yuque/0/2026/png/63601471/1781925584209-a8499195-daf5-4a09-98f3-91ddd89ea753.png)

  

**trampoline蹦床页，是全局映射的**。用户页表和内核页表都可以访问其指令，这为内核态与用户态转换后的代码执行提供支持。

  

XV6在每个user page table映射了trapframe page，这样每个进程都有自己的trapframe page。trapframe陷阱帧的作用是**保存用户态中断时上下文**。包含指向当前进程内核栈的指针、当前CPU的`hartid`、`usertrap`的地址和内核页表的地址和32个通用寄存器的状态。（你可以在proc.h中参阅struct trapframe）

对陷阱帧的了解还需要补充

  

**usertrap（在kernel/trap.c中），该函数会确定陷入的原因，处理并返回。**它会先改变stvec的值，让其指向kernelvec，还会再次保存程序计数器的值。如果陷阱来自系统调用，会显式打开中断，之后`syscall`会处理它；如果是设备中断，`devintr`会处理；否则它是一个异常，内核会杀死错误进程。usertrap在退出时会检测进程是否已被杀死，是否是个时钟中断而让出cpu。确认无误，便会执行usertrapret函数

**usertrapret**该函数设置RISC-V控制寄存器，为恢复中断前的状态做准备。函数将`stvec`更改为指向`uservec`，准备`uservec`所依赖的陷阱帧字段，并将`sepc`设置为之前保存的用户程序计数器。最后，`usertrapret`在蹦床页面上调用`userret`；原因是`userret`中的汇编代码会切换页表。

  

**userret执行过程中：**（`a1` = 进程用户页表的物理基址（用于写入`satp`），`a0` = 当前进程的`trapframe`虚拟地址）首先将a1与satp交换，之后sscratch会预存a0，再以a0为基地址，恢复全部用户通用寄存器，再将a0与sscratch交换。最后使用sret指令返回用户态。

  

## 从内核空间陷入

内核陷入时，**stvec指向kernelvec（kernel/kervelvec.S）**，因为没有系统状态（页表）的转换，内核陷入较为简单，他会做以下动作。

1. 被中断的内核线程的寄存器保存在其栈上。
2. 调用kerneltrap，判断中断类型和处理陷入（如果是时钟中断就调用yield, 为其他线程让步）
3. 恢复寄存器并执行sret

  

这些处理程序都要在关中断情况下中进行，且当用户态转换到内核态是stvec应该保存kernelvec的地址，你可以在trap.c/usertrap中看到这些实现细节！

  

  

# 缺页错误PageFault

**用户空间的异常，系统会中止进程，内核空间的异常，内核会崩溃。**

Risc-v有三种不同的页面错误: 加载页面错误 (当加载指令无法转换其虚拟地址时)，存储页面错误 (当存储指令无法转换其虚拟地址时) 和指令页面错误 (当指令的地址无法转换时)。`**scause**`**寄存器中的值指示页面错误的类型，**`**stval**`**寄存器包含无法翻译的地址。**

书中介绍了更多利用缺页错误来实现的有趣功能：

原理是：**故意将页面映射为只读**。**当进行写/存储操作时**，**触发页错误，在内核处理程序中动态分配内存并复制页面副本。**

  
**COW 写时拷贝**

在fork时**让父子进程共享所有物理页面，但将其映射为只读。**当父子进程进行写操作时，触发缺页异常。它在子级的地址空间中映射一个权限为读/写的副本，在父级的地址空间中映射另一个权限为读/写的副本，更新页表后就能正常执行写指令。

**Lazy Allocation懒分配**

进程调用 `sbrk()` / `malloc()` 申请**堆内存**时，**内核不立刻分配物理内存**，只扩大进程虚拟地址空间，将新增虚拟页标记为「未分配、无物理映射、不可访问」。当进程需要读写该虚拟内存时，触发缺页异常，让trap去分配实际物理内存。

  

**磁盘分页**

磁盘分页也叫**虚拟内存交换（Swap）**，核心逻辑和懒分配、COW 同源：依靠**缺页异常**，把不常用的物理页写到磁盘交换分区释放内存；需要访问时再从磁盘读回物理内存。
